# environmentsentry — Complete Example Project

A full end-to-end example showing environmentsentry in a Node.js + Express project.

---

## Project structure

```
my-app/
├── .env.sample              # Documented env variables (commit this)
├── .env                     # Real values (NEVER commit this)
├── .env.production          # Production env (generated by environmentsentry prod)
├── .environmentsentry-vault.sqlite  # Encrypted vault (NEVER commit this)
├── .environmentsentry-vault.key     # Vault encryption key (NEVER commit this)
├── package.json
├── src/
│   ├── index.ts             # Entry point
│   ├── config.ts            # Reads process.env
│   └── services/
│       └── db.ts            # Uses DATABASE_URL
└── docs/
```

---

## Step 1: Create `.env.sample`

```bash
cat > .env.sample << 'EOF'
############## Server
PORT=3000
NODE_ENV=development

############## Database
DATABASE_URL=postgres://localhost:5432/mydb
DB_POOL_SIZE=10

############## Auth
JWT_SECRET=
JWT_EXPIRY=24h

############## External
STRIPE_KEY=
SENDGRID_KEY=
EOF
```

---

## Step 2: Generate `.env` from sample

```bash
environmentsentry fix -e .env.sample
```

Output:
```
✓ Created .env from .env.sample
ℹ Now fill in your real values, then run: environmentsentry check
```

Now edit `.env` and add your real values (never commit this file):

```bash
# .env
PORT=3000
NODE_ENV=development
DATABASE_URL=postgres://admin:secret@localhost:5432/mydb
DB_POOL_SIZE=10
JWT_SECRET=my-super-secret-jwt-key
JWT_EXPIRY=24h
STRIPE_KEY=sk_test_...
SENDGRID_KEY=SG.....
```

## Step 4: Scan source code usage

Create `src/config.ts`:

```typescript
import * as dotenv from 'dotenv';
dotenv.config();

export const config = {
  port: parseInt(process.env.PORT || '3000', 10),
  nodeEnv: process.env.NODE_ENV || 'development',
  databaseUrl: process.env.DATABASE_URL,
  dbPoolSize: parseInt(process.env.DB_POOL_SIZE || '10', 10),
  jwtSecret: process.env.JWT_SECRET,
  jwtExpiry: process.env.JWT_EXPIRY || '24h',
  stripeKey: process.env.STRIPE_KEY,
  sendgridKey: process.env.SENDGRID_KEY,
};
```

Create `src/services/db.ts`:

```typescript
import { config } from '../config';

export function connectDatabase() {
  console.log(`Connecting to ${config.databaseUrl}`);
  // ... database connection logic
}
```

Create `src/index.ts`:

```typescript
import { config } from './config';
import { connectDatabase } from './services/db';

connectDatabase();

// Start server
console.log(`Server running on port ${config.port} in ${config.nodeEnv} mode`);
```

Now scan:

## Step 5: Store sensitive values in vault

```bash
# Initialize vault
environmentsentry vault init

# Store DATABASE_URL (encrypted at rest)
environmentsentry vault set DATABASE_URL "postgres://admin:secret@localhost:5432/mydb"

# Store JWT_SECRET
environmentsentry vault set JWT_SECRET "my-super-secret-jwt-key"

# Retrieve (masked)
environmentsentry vault get DATABASE_URL
# ****  (sha256: 9d5dcb8175777c31…)

# Retrieve with plaintext (--reveal)
environmentsentry vault get DATABASE_URL --reveal
# postgres://admin:secret@localhost:5432/mydb

# List all keys
environmentsentry vault list
# ✓ DATABASE_URL  2026-10-18T...  hash: x7y8z9…
# ✓ JWT_SECRET    2026-10-18T...  hash: a1b2c3d4…
```

## Step 6: Production setup

```bash
environmentsentry prod --force
```

This validates all vars, creates `.env.production`, and runs `npm test`.

## Step 7: Add to CI/CD

`package.json`:

```json
{
  "scripts": {
    "env:check": "environmentsentry check --strict",
    "env:fix": "environmentsentry fix",
    "predeploy": "environmentsentry check --strict"
  }
}
```

GitHub Actions (`.github/workflows/env-check.yml`):

```yaml
name: Env Check
on: [push, pull_request]
jobs:
  env-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm install -g environmentsentry
      - run: environmentsentry check --strict
```

## Quick commands reference

| Command | Purpose |
|---|---|
| `environmentsentry fix -e .env.sample` | Create `.env` from sample |
| `environmentsentry check` | Diagnose env vars (styled table) |
| `environmentsentry check --strict` | Exit 1 if any issues (CI/CD) |
| `environmentsentry usage` | Scan source for env references |
| `environmentsentry example` | Generate `.env.sample` from source |
| `environmentsentry prod --force` | Validate + create `.env.production` + test |
| `environmentsentry vault init` | Initialize encrypted vault |
| `environmentsentry vault set <k> <v>` | Store encrypted value |
| `environmentsentry vault get <k>` | Read value (masked) |
| `environmentsentry vault get <k> --reveal` | Read value (plaintext) |
| `environmentsentry vault list` | List keys only |
| `environmentsentry vault remove <k>` | Delete key |
